- [ ] 领域切换平滑过渡（**LRU 之上的策略层，非重写缓存**）
  - LRU 天然平滑：淘汰=最久未用先走，不做主动清空时旧领域专家自然衰减，新领域按需进入
  - 做法：① 不主动 clear（代码里禁掉"切换领域→cache.clear()"）② 共享专家靠 LRU 命中率自然保留 ③ 预热=检测到路由漂移→手动 insert 目标领域专家抬高 LRU 优先级
  - 依赖：模式 B/门控在线自适应提供"路由漂移"信号触发预热；共享专家清单从 collect 数据统计
  - 实施位置：排在门控在线自适应之后；预计几十行策略代码，A3 LRU cache 已提供底层机制
- [ ] LRU expert 缓存（Phase 3 GPU LRU cache 已实测，边界已确认）
- [ ] **cache 优化——挂 sched 拷贝层（2026-08-02 记录，host buffer 突破后的最后一公里）**
  - **现状**：A3 LRU cache 挂在 mul_mat_id 计算层，但专家拷贝发生在 sched 层（更早更底层），cache 是死代码；host buffer 形态下 sched 的 MoE 专家级拷贝优化只拷激活专家（DS 每层 9.3MB 而非 99MB），已给出 DS 37.5 / Qwen 46.8 t/s
  - **做法**：改 `ggml-backend.cpp` 的 `copy_experts`（1580 行 MoE 专家拷贝优化），拷之前先查 cache——命中 → D2D 拷贝（~3µs），miss → 才从 CPU pinned 搬（PCIe）+ 写 cache
  - **预期**：热专家稳定后每 token ~250MB PCIe 流量（DS，27 层 × 9.3MB）大部分消失，DS/Qwen 可能再提速 30-100%（逼近全 GPU 65/137 t/s）
  - **代价**：中等（sched copy_experts 加 cache 查询 ~50-100 行 + 复用 expert-cache.cu）；需 DS/Qwen/Mixtral 回归；命中率是收益上限
  - **排期**：host buffer 已交付 3 倍提速，此项靠后做（冲全 GPU 速度用）
- [ ] **门控在线自适应 + 模式 B（proxy 边用边收集）**：推理中读 LLAMA_EXPERT_LOG 实时路由，动态调缓存优先级（LRU 智能增强）；按会话累积路由画像
