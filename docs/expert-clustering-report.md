# MoE 专家聚集性验证报告

> 时间：2026-07-28（最新更新 2026-07-29）
> 模型：DeepSeek-V2-Lite (Chat-Uncensored, Q2_K 量化) + Qwen3.6-35B-A3B (IQ2_M)
> 结构：DS-V2-Lite=27层（层0 dense，64选6），Qwen3.6=40层（256选8×2 gate）
> 状态：Phase 1 CPU 验证 ✅，Phase 2 GPU 验证 — Qwen3.6 跨域路由数据采集 **全部完成** ✅（8域×3阶段=24批次），方向A 修复可用 🚧

---

## 结论

**MoE 路由器存在领域聚集性，但不同模型的表现形式截然不同：**
- DS-V2-Lite（64专家）：领域间专家集合**几乎互斥**（Python vs 路由器零交集）
- Qwen3.6（256专家，A3B）：全局所有 256 专家**在所有7个域都出现**，但**每层内部有 47-78% 的专家是域专属的**

这一发现表明：**MoE-L2 架构假设（领域→专家聚集性）是正确的，但约束条件因模型而异。** 在"细粒度"MoE（256+专家）中，聚集性体现在每层分布上，而非全局专家集合。

---

## 验证方法

### Phase 1 (DS-V2-Lite, CPU)
在 llama.cpp 的 `graph_compute` 函数中，`ggml_backend_sched_graph_compute_async` 成功后读取 `ffn_moe_topk-{层号}` tensor 的 `int32_t` 值。3组 prompt 对比（hi, Python, 路由器），详见 `moe-l2-领域聚集性验证报告-20260721.md`。

### Phase 2 (Qwen3.6, GPU — AutoDL RTX 4090 24GB)
`LLAMA_EXPERT_LOG=1` 环境变量控制 expert log 输出，通过 `ggml_backend_tensor_get()` 在 graph compute 完成后从 GPU 读取 expert index。**方向A 路径** — 不修改 graph 拓扑，无崩溃风险。

**测试配置：**
| 参数 | 值 |
|------|-----|
| GPU | RTX 4090 24GB (AutoDL) |
| 模型 | Qwen3.6-35B-A3B-UD-IQ2_M.gguf (11GB) |
| 量化 | IQ2_M (2-bit)，256 专家/层，top-8×2 |
| VRAM idle | ~978 MiB |
| VRAM running | ~1725-2249 MiB |
| 生成速度 | 5.0-5.7 t/s |
| Batch prompt | `-n 512` (longtail 阶段) |

**测试域（8个）：**

| 域 | 标签 | 描述 |
|----|------|------|
| codegen | 编程生成 | 生成 web 服务器、排序算法等 |
| debug | 代码调试 | 分析崩溃日志、修复 bug |
| math | 数学推理 | 微积分、概率计算 |
| logic | 逻辑谜题 | 推理题、约束求解 |
| general_qa | 通用问答 | 知识性问答题 |
| chinese_tech | 中文技术 | 技术概念的中文解释 |
| creative_write | 创意写作 | 故事、诗歌创作 |
| translate | 翻译 | 英译中技术文档 ✅ |

**每个域分 3 阶段：**
- **short**（`-n 128 -c 512`）：短生成，约 131 tokens → 5240 行 expert log
- **followup**（`-n 8 -c 1536`）：追问，约 11 tokens → 440 行
- **longtail**（`-n 512 -c 1024`）：长尾生成，约 515 tokens → 20600 行

**数据规模：** 8域 × 3阶段 = 24个 exhaust log，共 ~224,000 行 expert 路由记录（每行 40 层 × 16 expert = 约 3,580,000 个 expert 选择）

## 核心发现

### 1. 全局：所有 256 专家在所有域都出现（与 DS-V2-Lite 根本不同）

Jaccard 相似度矩阵（基于专家全集）：

```
          codegen  debug   math    logic   gen_qa  chinese_tech  creative_write
codegen    1.000   1.000   1.000   1.000   1.000   1.000        1.000
debug      1.000   1.000   1.000   1.000   1.000   1.000        1.000
...
```

**所有8个域的跨域 Jaccard = 1.000。** 每个域的 256 个专家完全相同。

**与 DS-V2-Lite 的关键反差：**

| 指标 | DS-V2-Lite (64 exp) | Qwen3.6 (256 exp) |
|------|-------------------|------------------|
| 全局专家交集 | Python vs Router：**零交集** | 7 域全部：**100% 交集** |
| 每层专家数 | 6/token | 16/token（8+8 gate） |
| Expert 粒度 | 64 个粗粒度专家 | 256 个细粒度专家 |
| 骨干专家 | 2 个（1, 11） | 10 个（top-15 交集） |

**解读：** Qwen3.6 的 256 专家是高度细粒度的。模型的知识不是"拆成 256 块各管一摊"，而是"256 个微小知识单元的组合"。模型可以不换专家全集，只换每层的激活分布。

### 2. 跨域聚集性出现在**每层级别** — 随深度递增

**逐层跨域 Jaccard 相似度（所有 7 域的两两平均）：**

| 层范围 | 平均 Jaccard | 域专用专家比例 | 类别 |
|--------|-------------|--------------|------|
|| L00-L05（浅层） | 0.876-0.982 | **5-32%** | **高共享** — 基础语言能力 |
|| L06-L15（中浅层） | 0.650-0.862 | 32-65% | 中等 — 部分域分化 |
|| L16-L25（中深层） | 0.550-0.648 | 60-72% | 低 — 域分化明显 |
|| L26-L34（深层） | 0.553-0.623 | 66-72% | 低 — 域分化持续 |
|| **L35-L36（最深层）** | **0.480-0.517** | **78-79%** | **最低共享 — 最强烈域分化** |
| L37-L39（输出层） | 0.555-0.682 | 55-73% | 回升 — 共享输出格式 |

**关键模式：**
- **L02** 是跨域最相似的层（Jaccard=0.982），仅 **4.7%** 的专家是域专属的
- **L35** 是跨域最不相似的层（Jaccard=0.471），**78.4%** 的专家是域专属的
- **前 3 层和后 2 层的专家共享度高** — 基础处理 + 输出格式可能是全局的
- **L10-L34 的专家，60-72% 是域专属的** — 这是 MoE-L2 可以优化的主要区域

**MoE-L2 意义：** 域预测器（L0a）的判定→对浅层（L0-L5）影响小（缓存策略不需要域感知），但对中深层（L6-L36）影响大（域专属专家占比 60-78%），可以节省大量 H2D 拷贝。

### 3. 10 个骨干专家出现在所有域的 Top-15

```
Experts in ALL domains' top-15: 10
  IDs: [41, 72, 89, 95, 112, 127, 191, 217, 221, 231]
```

**Expert 112** 是全局最活跃的（每域 Top-1 或 Top-2），但不是出现在所有层——它出现在仅 10-14/40 层中。这些骨干专家是 **层特定的"热专家"**，不是每层的"常驻专家"。

相比之下，DS-V2-Lite 的骨干专家（1, 11）在所有 prompt 的所有层都出现。Qwen3.6 的骨干专家只在**特定层**出现，但跨域一致性高。

### 4. 激活分布相对均匀（和 DS-V2-Lite 不同）

| 域 | Gini | Top-5% 占比 | Bottom-50% 占比 |
|---|------|------------|----------------|
| codegen | -0.265 | 9.8% | 30.9% |
| debug | -0.271 | 10.1% | 30.5% |
| math | -0.262 | 9.9% | 31.0% |
| logic | -0.262 | 9.8% | 31.1% |
| general_qa | -0.261 | 9.9% | 31.3% |
| chinese_tech | -0.259 | 9.9% | 31.3% |
| creative_write | -0.256 | 9.8% | 31.9% |
| translate | -0.275 | 10.1% | 30.3% |

**所有 8 域分布几乎完全相同！** Top-5% 专家占约 10% 激活，Bottom-50% 占约 31%。这意味着 Qwen3.6 的专家使用比 DS-V2-Lite 均匀得多——没有明显的"强者恒强"模式。translate 域的分布最均匀（Gini=-0.275，Bottom-50% 占比最低 30.3%）。

### 5. 最具域判别力的专家（跨域差异最大）

| Expert | CV | 域分布（各域激活次数） |
|--------|-----|----------------------|
| **5** | **0.877** | codegen:4, debug:2, **math:10**, logic:1, gen_qa:1, chinese:4, creative:4, translate:3 |
| 28 | 0.630 | codegen:3, debug:3, **math:13**, logic:5, gen_qa:7, chinese:3, creative:4, translate:3 |
| 118 | 0.622 | codegen:4, debug:1, math:5, logic:7, gen_qa:7, chinese:2, creative:4, translate:4 |
| 101 | 0.542 | codegen:4, debug:3, math:4, logic:3, gen_qa:8, chinese:10, creative:6, translate:3 |
| 155 | 0.413 | codegen:6, debug:8, **math:10**, logic:7, gen_qa:7, chinese:8, creative:6, translate:5 |

Expert 5 和 Expert 28 明显偏数学域（但 CV 绝对值不高，因为 8 域太相似，翻译域的加入均匀化了跨域分布）。

**与 DS-V2-Lite 的彻底对比：** DS-V2-Lite 上 Python vs 路由器域，许多专家是**一方有另一方完全没有**（完全判别）。Qwen3.6 上没有这样的"专属专家"——差异是量级上的，不是质上的。

## DS-V2-Lite vs Qwen3.6：对比总结

| 维度 | DS-V2-Lite (64 exp, top-6) | Qwen3.6 (256 exp, top-8×2) |
|------|---------------------------|---------------------------|
| 每层输出专家数 | 6 | 16（8+8） |
| 激活专家比例 | 6/64 = 9.4% | 16/256 = 6.25% |
| 跨域专家全集 | Python vs Router：**零重叠** | 8 域：**100% 重叠** |
| 骨干专家 | 2（1, 11）— 所有层所有域出现 | 10（41, 72, 89, 95, 112, ...）— 特定层跨域一致 |
| 每层域专属比例 | 未精确测量，但 Python 专属 > 50% | 中深层 **60-78%** |
| 专家使用分布 | 高 skew（部分专家明显更活跃） | 低 skew（相对均匀） |
| 激活集中度（Top-5%） | 未测量 | ~10% |

### 为什么会不一样？

推测两个原因：

**1. 专家粒度差异（主要）**：64 个粗粒度专家 vs 256 个细粒度专家。DS-V2-Lite 选 6/64 = 9.4%，相当于每层仅用一小部分专家"大模块"；Qwen3.6 选 16/256 = 6.25%，选中的专家数量更多但占比更小。如果 DS-V2-Lite 的每个专家是"一个大领域"，换域就得换专家；Qwen3.6 的每个专家是"一个小模式片段"，域差异通过不同专家的组合表达。

**2. A3B 架构影响**：Qwen3.6 是"激活 3B/35B"（A3B），意味着 35B 参数 × 256 专家中，每 token 只能激活 3B。路由器的选择必须更广泛覆盖知识。DS-V2-Lite 的 total params 更小（~16B？），每个专家含更多参数。

## 对 MoE-L2 架构的意义

### 1. L0a 域预测器的价值得到确认 ✅

虽然 Qwen3.6 的专家全集跨域相同，但**每层的专家分布差异显著**（最深层的 Jaccard 仅为 0.47）。域预测器判定后，可以：
- 对 **L0-L5（20% 共享）**：不需要域感知，缓存策略相同
- 对 **L6-L36（60-78% 域专属）**：按域预载特定专家，可省大量 H2D

### 2. LRU 缓存策略需要调整

DS-V2-Lite 场景下 LRU 可以按"域→专家集合"映射预载。Qwen3.6 场景下 LRU 需要：
- **按层独立缓存**: 每层的专家集不同，不能跨层共享
- **域感知的逐层预算分配**: 不同域需要不同的每层缓存策略
- **骨干专家优先保障**: 10 个跨域骨干专家的 H2D 延迟对一致性影响小（它们在所有域都活跃）

### 3. 需要验证更多 MoE 模型

Qwen3.6 和 DeepSeek-V2-Lite 的路由行为差异表明，**MoE 路由策略是架构相关的**。要构建通用 MoE-L2 方案，需要验证更多模型：
- DeepSeek-V2-Lite (64 exp ✅) → Qwen3.6 (256 exp ✅) → DeepSeek-V3 (256+ exp?)
- Qwen2.5-MoE (128 exp?)
- Mixtral-8x7B (8 exp — 完全不同的路由行为)

### 4. 缓存化的保底收益

即使不考虑域预测（简单的 LRU per-layer cache），Qwen3.6 这样细粒度的路由也有缓存潜力：
- 每层 256 专家中，每 token 只选 16 个
- N 个 token 后，很多专家会被重复选择
- 跨域 7 个域的 Top-5% 专家分布完全相同（意味着骨干专家集是稳定的）
